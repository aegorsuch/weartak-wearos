# Position log (incomplete implementation)

Position logging is separate from application diagnostics and is disabled by default.
Enabling it in Developer Options records the watch UID and GNSS fixes in app-private
storage. Export is explicit; the CSV contains sensitive location history.
Storage retains at most 50,000 fixes, discarding older entries and flagging the
log as incomplete when retention removes entries.

The timestamp is the Android fix time in UTC (ISO 8601). Coordinates are WGS84
decimal degrees. `horizontal_accuracy_m` is Android `Location.accuracy`, the
estimated 68% horizontal confidence radius in metres, not ground-truth error;
it is empty when unavailable.

This is not yet a complete evaluation log: dispositions are `unknown` and
relay is blank. A successful direct TAK Server or multicast socket write adds
`TAK_SERVER` or `MULTICAST` to bearer and `socket_written` to its status;
`not_written` includes failures and sends prevented before socket write. A
SITX WebSocket accepting a message into its send queue adds `SITX` and
`api_accepted`; `not_accepted` means no socket accepted it or the command
queue rejected it. A blank status means no result was observed, not failure.
Bearer lists only observed successful handoffs, separated by semicolons; other
routes are not tracked. Neither a socket write nor API acceptance confirms
receipt. Only snapshots
whose coordinates match the original location provider are correlated. Socket
writes are asynchronous, so timing relative to the fix is not inferred. The
recorder observes active Android location callbacks, not fixes generated by
hardware or other devices outside those callbacks. Repeated callbacks for the
same provider, fix timestamp, elapsed time and coordinates are deduplicated.
The incomplete-storage warning persists after a queue or storage failure; an
export remains available for recovering the records that were saved. Queued
fixes may be lost on abrupt process termination.

Developer Options can export the CSV or create a ZIP with a TAK mission-package
manifest, CSV, application diagnostics and a privacy note. The system document
picker is required for file export. Alternatively, upload the package to a
selected connected TAK Server; this does not notify recipients, so share the
displayed SHA-256 hash separately. Server permissions control who can retrieve
the upload. Offline transfer without a document provider and tracking plugin or
companion routes are not implemented.
